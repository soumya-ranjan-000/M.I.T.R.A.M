# Changelog

## 0.7.0

- **GPT models on Azure OpenAI, and other OpenAI-compatible endpoints:** set `mitram.openai.endpoint` to your Azure OpenAI resource (`https://<resource>.openai.azure.com/`) or any OpenAI-compatible base URL, list your deployment names in `mitram.openai.models`, and set the key with **M.I.T.R.A.M: Set OpenAI API Key**. Those models appear in the model picker next to Claude and get the same tools, approvals and plan board; a chat can switch between them. On Azure the deployment's `chat/completions` URL is called with `mitram.openai.apiVersion` (default `2024-12-01-preview`). The endpoint is read from user settings only, and its key is kept in VS Code's secret storage. PDFs attached to a message cannot be sent to these models.
- **Whole command output:** a running command's card now shows its whole log as it arrives, not just the latest lines, in a window that follows the newest line unless you scroll up to read. When the command finishes the card folds away and shows its exit code; a command that failed keeps its last lines in view. The agent still gets the whole output when the command finishes.
- **Background terminals:** the agent can start a dev server, watcher or anything else that does not finish on its own with `run_command` and `background: true`. The command keeps running after the call returns with its first few seconds of output; the agent checks on it with `read_process_output`, lists them with `list_processes` and stops one with `stop_process` (which asks first, like starting one). A chip above the message box (**2 running · 1 ended**) opens a panel with each process's live output and buttons to **Stop** it (and everything it started), **Restart** it, **Open in terminal** (a VS Code terminal showing its output, where what you type goes to the process and Ctrl+C stops it), **Copy** the output, or **Ask the agent** about it. A background command's card links to its output. Processes keep running across chats and runs, are stopped when the chat that started them is deleted, and are all killed when VS Code closes; at most eight run at once. In plan mode the agent can read their output but not start or stop them. Coloured output is shown as plain text in the chat.
- **Chats keep working in the background:** starting a new chat or switching to another no longer stops the agent. Each chat runs on its own, with its own approvals, Stop button, queued messages and "always allow" choices; Stop affects only the chat on screen, and deleting a chat stops its run. A new chat shows the others under **Other chats**: what each is doing and for how long, which one needs your approval, and which finished, paused or failed while you were away. Click one to open it. The history button shows how many other chats are working (amber when one is waiting for you), and lists working chats first. Coming back to a chat shows its error, pause or finished plan as if you had stayed. Notifications now name the chat, are not held back because a different chat is on screen, and **Open chat** opens the right one. At most `mitram.maxConcurrentRuns` chats (3 by default) work at once; others wait their turn. If another working chat has already changed the file an edit would touch, its approval prompt says so. A chat now appears in the history list as soon as you send its first message.
- **Every file the chat changed, above the message box:** a panel lists each file the agent created, changed or deleted in this chat, with lines added and removed compared with before the chat, and keeps updating while the agent works. Click a file for a diff from before the chat to now (the right side is the real file, so you can edit it there), or use its buttons to open it or put it back. **Revert all** restores every file after asking; **Keep** accepts the changes and clears the list; **Undo last turn** replaces the old "files changed in the last turn" bar. Files the chat created are moved to the trash when reverted, and the agent is told what you reverted. The list survives a reload: earlier versions are kept next to the chat history (up to 2 MB per file) and deleted with the chat. Files changed by commands the agent ran are not listed.
- **Steps fold away:** the tool calls, reasoning and attached files between two replies are shown as one line, such as "Read 3 files, ran 2 commands · 6 steps", with a warning sign if any of them failed. While the agent works, the line shows only what is running; when it is done, it folds. Approval prompts are always shown. Click the line to see every step, or turn this off with `mitram.collapseToolCalls`.
- **Quieter tool output:** tool cards and reasoning are drawn fainter than the conversation, and come back to full strength when you hover over or focus them. Approval prompts and failed calls are never faded, and nothing is in high-contrast themes.
- **Reasoning:** the reasoning block follows the newest text while it streams, folds when the model moves on, and says how long it thought.
- **Image preview:** hover over or focus an attached image, in a sent message or in the message box, to see it larger with its size.

## 0.6.0

- **Talk to the agent while it works:** type while a run is going and press Enter. The message joins the run and the agent reads it after its current step, so a running command is no longer killed to make way for it. While you are typing, Send takes the place of Stop; Esc still stops. A line under the working status shows that your message is queued until the agent picks it up. A message sent while an approval is waiting declines that action, and the message tells the agent what to do instead. Switching plan mode on or off still starts a fresh run.
- **Live command output:** a running command's card shows its latest lines as they arrive, so long test runs and builds are no longer just a spinner. Open the card to see all of it. The agent still gets the whole output when the command finishes.
- Fixed: a chat could get stuck on `400 … tool_use ids were found without tool_result blocks` after you sent a message while a command was running, or reloaded the window mid-run, and every later message and Retry failed with the same error. A new message now waits for the interrupted run to record its results, and a chat already stuck this way is repaired on its next message.
- Fixed: a run that was interrupted no longer clears the next run's approval prompts or ends its working indicator.

## 0.5.0

- **Atlassian sign-in with OAuth:** the Atlassian entry in the MCP panel now signs you in with your Atlassian account in the browser, as Atlassian's hosted server expects, instead of asking you to paste an API token. Pick it and approve access; there is nothing to copy. M.I.T.R.A.M registers itself with the server on the fly (OAuth 2.1 with PKCE), so no client id or secret is built in, and renews the access automatically afterwards. If the saved sign-in stops working, the server shows **Sign in** in the panel and a one-time message offers it; nothing opens a browser behind your back. **Sign out** forgets it. The sign-in is kept in VS Code's secret storage, never in settings, and only `https` sign-in pages are opened. Any other remote server that supports it can use `"auth": { "kind": "oauth" }`, or **Custom…** → **Sign in with your browser (OAuth)**. The old API-token entry is gone; a custom server can still use a token if your Atlassian admin has enabled that.

- **Notifications:** when the agent needs your approval, finishes a run, pauses or hits an error while VS Code is not in front, you get an operating system notification, on Windows, macOS and Linux (Linux needs `notify-send`). If VS Code is in front but the chat is hidden, you get a VS Code message with an **Open chat** button instead. Runs that finish in under eight seconds are not announced. Choose `whenAway` (default), `always` or `off` with `mitram.notifications`. The text is the action's one-line summary, such as `Run npm test`. When VS Code runs on a remote machine, VS Code messages are used.
- **See what changed:** click a finished edit or file-creation card in the chat, or its **View diff** link, to open VS Code's diff editor on exactly what that call changed, including calls made by sub-agents. The diff is a snapshot, so it stays right if you edit the file afterwards. Snapshots are kept until the window reloads, and skipped for files over 2 MB.
- **Voice prompts:** the microphone button next to Send opens a small page in your browser, which listens and sends the text back into the message box for you to review. A VS Code chat view cannot use a microphone, so this works the same on every OS, over Remote SSH and WSL too, and needs nothing installed. By default it uses the browser's own speech recognition (Chrome, Edge or Safari). Set `mitram.voice.provider` to `endpoint` to record instead and transcribe through any OpenAI-compatible endpoint (OpenAI, Azure OpenAI, Groq, or a local Whisper server) at `mitram.voice.endpoint`; set its key with **M.I.T.R.A.M: Set Voice API Key**. The page opens as a small window with no tabs or address bar (Chrome, Edge, Brave or Chromium; `mitram.voice.compactWindow`) and closes itself when you are done, or in your default browser if none is installed. It is served on `127.0.0.1` for one dictation only, behind a one-time token.
- **Filesystem MCP server on Windows:** the folder is now written the way Windows programs expect: quotes removed, `/` turned into `\`, a capital drive letter, no trailing backslash (which broke the argument when launched through `npx.cmd`), and `~` and `%USERPROFILE%` expanded. The wizard suggests your open project, checks that the folder exists, and shows a path in your platform's style. Servers already saved with such paths are fixed when they start. A local server may now take up to 90 seconds to start (the first `npx` run downloads it), and the agent is told to use drive-letter paths on Windows and to ask the server for its allowed folders.
- **Faster chat:** streamed text is sent in 40 ms batches and drawn once per frame, long replies re-render only their newest block, finished messages and tool cards are not redrawn, code highlighting is cached, and saving chats rewrites only the one that changed. A message's context, environment and MCP servers are now gathered at the same time rather than one after another.

## 0.4.0

- **Tools from MCP servers:** connect [MCP](https://modelcontextprotocol.io) servers to give the agent tools this extension does not have — a real browser, your issue tracker, a database. Open the **MCP servers** panel from the plug icon in the chat header or type `/mcp`, press **+**, and pick a ready-made entry (Playwright, GitHub, Filesystem, Atlassian, PostgreSQL, Sentry) or **Custom…** for any command or `https` URL. The panel shows each server's state, how many tools it offers, and buttons to set its key, disable, reconnect or remove it. Servers start on the first message that needs them; one that fails to start costs you its tools and nothing else. The agent sees them as `mcp__<server>__<tool>`, and is told their results are untrusted data it may act on but never take instructions from.
- **API keys for MCP servers** are typed into a password box and kept in VS Code's secret storage, never in `settings.json`, and are deleted with the server. A key can be sent as an HTTP header (`Authorization: Bearer …`, as hosted services such as Atlassian expect) or as an environment variable (`GITHUB_PERSONAL_ACCESS_TOKEN`, as local servers expect).
- **Security for MCP:** `mitram.mcpServers` is read from user settings only, so a cloned repository cannot add a server or switch one on. Running a server means running a program with your permissions, so the first start in a project asks for your agreement, and **every MCP tool call asks for approval** with its exact arguments shown — `mitram.skipApprovalPrompts`, which covers this project's own edits and commands, deliberately does not extend to them. `mitram.autoApproveMcpReads` can relax that for tools a server marks read-only, and `mitram.blockedMcpTools` refuses matching tools outright. In plan mode MCP tools are not offered at all. Logs record the server, the tool and how long it took, never the arguments, the results or the key.
- **Sub-agents:** the agent can hand a self-contained piece of work to a sub-agent with its own context, tools and brief, and several run at the same time (`mitram.maxParallelSubagents`, three by default). Only the final report comes back, so a long investigation no longer fills the main conversation. A sub-agent either explores (read-only) or implements (it can also edit and run commands, each still asking you first); it cannot touch the plan board and cannot delegate again, so work never fans out without end. In plan mode only exploring sub-agents are offered. Their steps appear indented under the delegation card. Turn it off with `mitram.subagents`.

## 0.3.0

- **Related code up front:** each message now carries the files a local keyword search matched to it (paths, line ranges and short excerpts from the top two, about 650 tokens), so the agent can start from the right code instead of searching first. It understands identifiers (`autoApproveEdits`, `cache_control`), word forms and common developer synonyms ("revert" finds code that says "restore"). Messages that name no code, such as "looks good, go ahead", usually attach nothing. A collapsed **Attached N related files** card under your message shows what was sent; click a file to open it at those lines. The index respects `.gitignore`, lives in memory and updates as files change. It is a starting point, not always right: the agent is told to check the files before relying on them. Turn it off with `mitram.retrieveContext`.
- **Skip approval prompts:** the user-level `mitram.skipApprovalPrompts` setting skips approval prompts for file edits, file creation and commands. Commands blocked by the safety policy remain blocked. Off by default, and ignored in a workspace's `.vscode/settings.json`.

## 0.2.0

- Fixed: hiding the chat (switching side bar views, or closing and reopening it) during a run lost the "Writing…" status, timer, stop button and glow while the agent kept working. The reopened view now picks the run back up, along with the context bar and the **Revert changes** bar.
- **Files in chat:** **+** → **Attach files…**, or a drop or paste from a file manager, attaches PDFs and Word, Excel, PowerPoint, LibreOffice and text files (up to 5 per message, alongside 5 images). PDFs are sent as documents, so the model sees their pages; other files as the text read from them, with spreadsheets as CSV for each sheet and real dates. Old PDFs are trimmed, counted toward the request size limit and left out of saved chats just like images.
- **Pinned request:** once your message scrolls out of view, it stays pinned at the top of the chat as a "Your request" card, two lines at most, so you can see what the agent is working on without scrolling back. It follows the part of the chat you are reading, skips the automatic "Continue" and "plan approved" messages, and jumps to the full message when clicked.
- **Images in chat:** paste a screenshot, drop an image, or use **+** → **Attach files…** (up to 5 per message). Images are resized to the model's limit (2576 px, 3.75 MP) and sent as image blocks, counted by their pixels when trimming context, and removed from older turns when a chat gets long or close to the request size limit.
- **Always allow** for commands: the approval card offers a rule for this workspace, such as `npm run lint *` or the exact command, so you no longer have to edit settings by hand. Commands with pipes, chaining, redirects or wildcards can be always allowed too, exactly as written only, with a warning on the card. Review or remove rules with `/permissions` or **M.I.T.R.A.M: Manage Always-Allowed Commands**.
- **Security:** `mitram.endpoint`, `mitram.autoApproveEdits`, `mitram.autoApproveSafeCommands` and `mitram.autoApproveCommands` are now read from user settings only. Values in a workspace's `.vscode/settings.json` are ignored, so a cloned repository can no longer send your API key to its own server or turn on auto-approval. If you set any of these per workspace, move them to your user settings (or, for commands, use **Always allow**).
- A long or multi-line command now shows in full on its approval card, instead of being cut off after one line.
- "Always allow" on edits is now labelled **Always allow in this chat**, to make clear it lasts for the current chat only.

## 0.1.0

First release.

- Chat panel in the activity bar, with streaming replies, markdown and highlighted code blocks (copy / insert at cursor).
- Works with Claude on **Azure AI Foundry**: set your endpoint and API key (stored in VS Code's secret storage).
- Agent that can read, search and edit your workspace and run commands, step by step, with a card for every action.
- Approval before edits and commands, with a diff preview, "always allow" for edits, and a **Revert changes** button for the last turn.
- Safety net for commands: dangerous ones are blocked outright, plus optional auto-approve for read-only commands and commands you list.
- Attach the current file, a selection, or `@file` mentions. Open tabs, git branch, diff summary and current errors are sent with each message (can be turned off).
- Saved chats, model picker (`/model`), plan mode (`/plan`), and slash commands.
- Automatic context trimming, prompt caching, and a context-usage bar.
- `MITRAM.md` project instructions.
- Local, redacted logs and a "Copy Diagnostics" command. No telemetry.
- Plan board: the agent keeps a visible task list and notes, saved with the chat and shown to it before every request.
- Long-run support: check-before-finishing, step and time budgets with a Continue button, detection of repeated actions, and summaries of old context.
- Streamed reasoning summaries, with an automatic fallback if the deployment does not support them.
- 29 end-to-end eval tasks, including five longer ones.
